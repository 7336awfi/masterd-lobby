## 一、业界 4 种「记忆持久化」架构

```
① 文件 + Git（简单）
   · 记忆存 Markdown/JSON + Git 版本控制
   · 优点：简单/可读/可审
   · 缺点：检索弱
   · ★ 三哥/我们用的就是这个

② SQLite + 全文检索（中等）
   · 记忆存 SQLite（结构化 + 全文索引）
   · ★ 三哥的 memory.py 是这个
   · 优点：快/可查/单文件

③ 向量数据库（语义）
   · 记忆 → embedding → 向量库
   · 优点：语义强（模糊召回）
   · 缺点：复杂/要模型/成本高

④ 混合（主流推荐）
   · 结构化 + 全文 + 向量（可选）
   → "分层检索"（先筛后召）
```

## 二、我的建议（供参考）

```
★ "先用简单可靠的（文件+Git），需要时加 SQLite"
· 别一上来就上向量（复杂、贵）
· 医疗（你）特别需要：★ "可删"（合规）
  → 能删单条、能删某"患者"全部
  → 你的记忆量会大（多个兄弟的体检数据）
  → SQLite 更适合你（查询/删除方便）
```
